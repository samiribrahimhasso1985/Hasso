# EZIDINET — online test server on Render (Blueprint)

**Status 2026-11-28: live at https://ezidinet.onrender.com** (Blueprint EZIDINET, branch `ccr-47c5f9b6-alewtl`).

`render.yaml` (repository root) creates, in Frankfurt (EU), on free plans:
* **ezidinet-db** — PostgreSQL 16, no internet access (only the service connects). Free databases are deleted by
  Render 30 days after creation unless upgraded — use for testing only.
* **ezidinet** — one web service: website at `/`, platform at `/app`, API only behind the `/api` proxy
  (`scripts/render-build.sh`, `scripts/render-start.sh`). Migrations and the relationship-type catalogue run at every
  start; **no demo people** online. Secrets (`JWT_SECRET`, `QR_TOKEN_KEY`, `OUTBOX_KEY`) are generated by Render.

Free web services sleep after ~15 minutes without visitors; the first visit then takes about a minute.

## Steps for the owner (no API key needed)
1. dashboard.render.com → **New → Blueprint**.
2. Connect GitHub if asked, and allow access to the repository **Hasso**.
3. Choose the repository **Hasso** and the branch **ccr-47c5f9b6-alewtl** → Render reads `render.yaml`.
4. **Apply / Deploy Blueprint**. The first build takes several minutes.
5. The address appears on the service page (e.g. `https://ezidinet.onrender.com`).

## After the first deploy
* E-mail links (confirm address, new password) are in the developer mailbox:
  `https://<address>/dev/mailbox?key=<OUTBOX_KEY>` — the key is under *ezidinet → Environment*. Keep it private.
* The Android app: enter `https://<address>` once (or a new build with the address pre-filled).
